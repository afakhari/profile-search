# گزارش کیفیت داده

این گزارش از فایل `data/raw/linkedin_profiles.csv` تولید شده است و فایل خام فقط خواندنی در نظر گرفته می‌شود. گزارش ماشینی و ردیف‌به‌ردیف در [`reports/import-report.json`](../reports/import-report.json) قرار دارد.

## نتایج بررسی‌شده

| معیار | تعداد |
|---|---:|
| ستون‌های سربرگ | ۷۷ |
| ردیف‌های خام | ۳۳۶ |
| ردیف‌های پذیرفته‌شده | ۳۰۷ |
| پروفایل‌های یکتا پس از حذف تکراری‌ها | ۲۷۰ |
| ردیف‌های تکراری ورودی | ۳۷ |
| ردیف‌های قرنطینه‌شده | ۲۹ |
| ستون‌های مسیر منبع حذف‌شده | ۲۵ |
| سوابق شغلی ذخیره‌شده | ۲٬۰۱۸ |
| سوابق تحصیلی ذخیره‌شده | ۸۲۱ |
| مهارت‌های نرمال‌شدهٔ یکتا | ۲٬۵۳۱ |

از ۲۹ ردیف قرنطینه‌شده، ۲۸ ردیف به‌جای ۷۷ ستون، بین ۶ تا ۱۳۳ ستون دارند که معمولاً نشانهٔ رکورد ناقص یا به‌هم‌چسبیده است. یک ردیف نیز تکرار سربرگ CSV است. این ردیف‌ها بدون حدس‌زدن یا ورود ناقص کنار گذاشته می‌شوند.

نشانی‌های LinkedIn بدون Scheme در هر ۳۰۷ ردیف پذیرفته‌شده به HTTPS نرمال شده‌اند. بعضی بخش‌های منبع جابه‌جایی ستون دارند؛ این موارد با تکیه بر لنگر پایدار `version_status` و ترتیب ثابت بلوک‌های سابقه، تحصیلات و شبکه‌های اجتماعی به‌شکل قطعی هم‌تراز شده‌اند. تمام این اقدامات برای هر ردیف در گزارش JSON ثبت شده‌اند.

واردکننده نتایج زیر را ثبت می‌کند و پنهان نمی‌سازد:

- تعداد ردیف‌های خام، واردشده، ترمیم‌شده، ردشده و تکراری؛
- خطاهای خواندن امن با `json.loads` یا `ast.literal_eval`؛
- ناهنجاری تعداد ستون‌ها و ترمیم قابل‌اثبات ستون اضافهٔ مسیر منبع؛
- ناسازگاری‌های معنایی، مانند نشانی نامعتبر LinkedIn یا میزان سابقهٔ غیرمنطقی؛
- بازیابی شغل فعلی مفقود از سابقه‌ای که به‌عنوان شغل اصلی مشخص شده است.

برای بازتولید گزارش، دستور زیر را اجرا کنید:

```bash
python manage.py import_profiles <file> --report reports/import-report.json
```

ردیف‌های نامعتبر کل فرایند ورود را متوقف نمی‌کنند و فایل اصلی نیز هرگز تغییر نمی‌کند.
